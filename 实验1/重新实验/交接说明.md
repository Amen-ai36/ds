- 请求次数：10；有效匹配响应：10；成功率：100%。
- offset：最小 285 ms，最大 291 ms，平均 287.30 ms。
- delay：最小 18 ms，最大 28 ms，平均 22.00 ms。

这些 offset 是相对该时间服务器的估计偏移，不是独立测量得到的绝对误差；10 次短期采样不代表长期可用性或精度保证。

## 给 A：可手算的正式公网样例

取第 1 次成功记录（Unix 毫秒）：

```text
T1 = 1794390125155
T2 = 1794390125449
T3 = 1794390125449
T4 = 1794390125173
offset = ((294) + (276)) / 2 = 285 ms
delay  = (18) - (0) = 18 ms
corrected = 1794390125173 + (285) = 1794390125458
```

偏移为正表示本地时钟相对该服务器落后。整数除法向零截断，NTP 小数四舍五入到毫秒。原理与符号可直接和这条记录核对。

## 给 C：数据与实验边界

1. 正常场景：`直连正式数据.csv`，对应原始控制台输出 `直连正式运行记录.txt`。
2. 迟到回包场景：`../验证记录/local_regression_rows.csv` 与 `../tests/NtpRegressionTest.java`。这是本地模拟，不作为公网精度数据。
3. 稳定超时场景：`../验证记录/console_local.csv` 第二条；本地模拟服务器刻意不响应。
4. 发送失败与地址失败：`../验证记录/local_regression_rows.csv` 第 3、4 条；独立控制台地址失败见 `../验证记录/dns_failure.csv`。
5. `wait_ms` 是接收等待时间（发送失败时为发送尝试耗时），`resolve_ms` 独立记录地址解析耗时。失败时未知时间戳和计算结果为空。
6. 每次运行日志是一次特定条件采样，不能将不同代理状态、超时参数和服务器的记录合并成同条件前后对比。

CSV 字段及请求匹配实现细节见 `../B成员反馈修复说明.md`。建议 C 独立复测更多样本，必要时跨节点比较一致性。

## 给 D：演示步骤与备用材料

在项目根目录执行：

```bash
bash "实验1/重新实验/直连重跑.sh"
```

脚本编译源文件后向阿里云时间服务器直连请求 10 次，间隔 5 秒，接收超时 2 秒；每次运行用时间戳命名日志，不覆盖正式样例。正常结果应显示 `NTP_Success`、T1–T4、offset、delay、local、corrected。

接着执行可复现的迟到包/故障演示：

```bash
javac -encoding UTF-8 -cp out -d out "实验1/tests/NtpRegressionTest.java"
java -cp out NtpRegressionTest
python3 "实验1/tests/run_console_mock.py"
python3 "实验1/tests/verify_logs.py"
```

应看到 `ALL REGRESSION TESTS PASSED` 和 CSV 核算通过。模拟测试证明旧包会被丢弃，不证明历史异常的具体成因。若现场公网不通，使用本地演示，并展示保存的正式公网日志，明确它是历史实测。
