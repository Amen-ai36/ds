# Raft 2C 持久化补丁

[补丁](raft-persistence.patch)以课程随附的 MIT 6.5840 骨架为基线，补齐 `src/raft/raft.go` 的 `persist()`、`readPersist()` 和 `Make()` 启动恢复。任期、投票对象和日志一起编码，通过 `Persister.Save(raftstate, nil)` 保存。解码使用临时结构，成功后才更新节点状态。编解码失败会报告节点编号并触发 panic。

## 在课程骨架上应用

在课程代码包的 `6.5840` 根目录运行以下命令，将 `<ds>` 替换为本仓库的路径。

```sh
git apply --check "<ds>/实验2/2C/raft-persistence.patch"
git apply "<ds>/实验2/2C/raft-persistence.patch"
```

补丁采用 `int` 保存任期和投票对象，`votedFor = -1` 表示尚未投票，日志暂用 `[]LogEntry`。接到 A、B 的版本时，沿用该版本的字段、日志类型和索引约定，并将补丁的三处读写逻辑接入对应位置。若 `Command` 中存放自定义类型，服务层需要先用 `labgob.Register` 注册，再启动 Raft。

## 与 2A、2B 接入

`persist()` 由持有 `rf.mu` 的调用方调用。修改持久状态的路径应在释放锁、发出依赖该状态的请求或返回响应之前完成持久化。

| 状态变化 | 接入位置 |
| --- | --- |
| 开始新一轮选举 | 增加 `currentTerm` 并自投后，在发出 `RequestVote` 前保存 |
| 发现更高任期 | 在处理 RPC 请求或响应时，更新任期并清空旧投票后保存。即使随后拒绝投票或日志追加，任期变化也要保存 |
| 授予投票 | 写入 `votedFor` 后，在回复同意前保存 |
| Leader 追加命令 | 在 `Start()` 中完成本地追加后、返回或开始发送该条目之前保存 |
| Follower 修改日志 | 在 `AppendEntries` 中完成冲突截断或追加后、回复成功前保存 |

`Make()` 先设置新节点的默认状态，再调用 `readPersist()`，随后启动选举、复制和应用协程。重启的初始角色由 2A 设置为 Follower。若有依赖日志末尾索引的初始化，在恢复日志后计算。

## 骨架验证

应用补丁的课程骨架在 Go 1.27.4 下连续三次通过以下四项检查。

- 空状态启动时，任期为 0，投票对象为 -1，日志为空。
- 使用保存的状态重新调用 `Make()`，恢复原任期、对节点 0 的投票，以及包含字符串和已注册自定义命令的日志。
- 截断的持久化数据触发解码错误，三个字段保持原值。
- 无法编码的日志命令触发错误，`Persister` 中保留上次成功保存的字节。
